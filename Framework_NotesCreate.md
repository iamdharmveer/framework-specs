## §1 — UNIT OF WORK AND INGEST
1. One run = one subtopic. The run FIRST builds the unit's PYQ bank: read the
   §3-resolved sorted papers, extract every question whose subtopic header
   matches the unit, and record for each: bank id, exam-date + Q number, type
   (MCQ/MSQ/NAT), full stem + options, concept tag(s), and a FIGURE flag when
   options or stem depend on embedded images.
2. The bank is CHECKPOINTED to a project artifact after every few papers
   (append-only), so an interrupted run resumes without re-reading.
3. The bank's frequency-tagged concept map (concept → question ids → star
   rating) is the input to §4's Concept Ladder ordering and star tags.

## §2 — CONTENT AUTHORITY (SME MODE + CARVE-OUT)
1. The memory ban stays ABSOLUTE for question generation and answer keys.
2. Notes CONTENT is SME-generated by Claude — no reference book required —
   and earns trust ONLY via Step NA's machine solvability audit. Content that
   has not passed NA is never delivered.
3. If a reference book is present in project Files or the resolved Drive
   sources, it is used as a GROUNDING reference (terminology, notation, level)
   — never copied. Absence of a reference is the normal case.
4. No human review exists anywhere in this pipeline; NA is the sole gate.

## §3 — PYQ PROTECTION (paraphrase rule)
Worked examples are PYQ-ANCHORED but PARAPHRASED: fresh numbers and fresh
wording, with the anchor recorded as exam-date + Q number. Actual PYQ text is
NEVER reproduced inside notes (protects the test-series product). The audit
bank (§1) is an internal artifact, not a delivered one.

## §4 — DOCUMENT ANATOMY (10 blocks, locked)
  B1  HEADER — title, Subject▸Topic▸Subtopic mapping line, doc code, badge
      table (PYQ count + year span, role tag, Level, solvability guarantee),
      star-legend + prerequisite cross-references BY UNIT CODE (never page).
  B2  CONCEPT LADDER — concepts in prerequisite order; bullets and tables per
      §5; schematic diagrams per §6.
  B3  KEY POINTS box after every concept.
  B4  Star frequency tags (★/★★/★★★) on concept headings, from §1.3.
  B5  WORKED EXAMPLES — per concept, PYQ-anchored (§3), covering ALL question
      types present in the bank: numerical → stepwise solve; conceptual →
      reasoning walkthrough / option elimination; MSQ → statement evaluation.
      A SPEED HACK line only where a genuine shortcut exists.
  B6  TRAP box — recurring wrong-option patterns evidenced by >= 2 bank
      questions each, with the evidencing years listed.
  B7  EXAM LENS — question-type mix for this subtopic mapped onto the Exam
      Pattern Range tab (marks + negative marking), plus attempt strategy.
  B8  RAPID REVISION SUMMARY — Must-Know Formulae table + Key Associations
      table (two-column, Exam-Mapping-book style).
  B9  RECALL CHECK — 5–8 retrieval prompts; answers set in reduced size,
      visually separated at the box foot.
  B10 MIND MAP — auto-generated concept graph, last page.
Blocks B5–B7 appear only where PYQ evidence warrants (always for TIER-1/2).
TIER-3 units may ship B1–B4 + B8–B10 only.

## §5 — DENSITY SPEC (machine-gated in NA; constants live in notes_core.py)
  D-1 Bullet length: target <= 20 words; HARD CAP 25.
  D-2 No prose paragraph longer than 2 rendered lines.
  D-3 TABLE-FIRST: >= 3 parallel facts MUST become a table.
  D-4 One concept occupies ~0.5–1.5 pages.
  D-5 Subtopic length ~ concepts x 1.2 pp; typical 6–10 pp; heavy TIER-1 max
      12–15 pp. 30–40 pp outputs are a spec violation, not thoroughness.
  D-6 Every fact must be syllabus-required, PYQ-anchored, or BRIDGE-justified.

## §6 — FORMAT RULES
  F-1 Naming: {EXAM}_S{s}_T{t}_ST{nn}_{Slug}.docx (e.g.
      IITJAM_BT_S1_T2_ST08_Enzyme_Kinetics.docx). Cross-references use unit
      codes, never page numbers.
  F-2 Page A4, font Arial throughout, ISHAI-consistent colour accents.
  F-3 Mathematics is OMML (same as the Test Framework). See NA §5 for the
      MANDATORY structural (non-visual) verification rule.
  F-4 Diagrams are auto-generated (matplotlib or equivalent), schematic-grade
      accepted; embedded as PNG; no human review.
  F-5 Language: English only, simple exam-coaching register.
  F-6 No version footer inside the document. Draft/version identifiers are
      displayed in chat only.
  F-7 docx line spacing: image and OMML paragraphs MUST NOT inherit a fixed
      line rule (clips tall inline objects — defect found and fixed in the
      Enzyme Kinetics sample). Use auto line rule document-wide.

## §7 — BATCHING AND STATE
One subtopic per run. A multi-unit request is split into per-unit runs with a
continue-confirmation between batches. On completion the unit's registry
record moves BLUEPRINTED → DRAFTED with notes_version set (starts 0.1; NA
patches bump the minor).
